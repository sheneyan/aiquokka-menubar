# aiquokka 显示模式设计

## 目标

在现有 macOS 菜单栏 App 中增加“菜单栏 / 独立窗口”显示模式。独立窗口可以拖到专用小屏，保留菜单栏图标作为控制和恢复入口；两种模式继续共享同一个本地 `aiquokka --yml` 数据源和刷新 Store。

## 用户行为

- 默认模式为“菜单栏”，保持现有菜单栏摘要和点击详情弹窗。
- 菜单栏详情中加入“显示方式”选择器，选择后立即生效，并保存到 `UserDefaults`。
- 选择“独立窗口”后，立即打开一个标准 macOS 窗口；窗口显示完整 provider、使用率窗口、重置时间和额外字段。
- 菜单栏图标始终保留。无论当前模式如何，点击图标都能刷新数据、切换显示方式或退出 App。
- 独立窗口也显示同一个“显示方式”选择器。切回“菜单栏”后窗口关闭，菜单栏弹窗成为唯一详情 surface。
- 用户直接关闭独立窗口时，显示方式自动改回“菜单栏”，避免偏好指向一个已经不存在的窗口。
- 如果上次退出时选择的是“独立窗口”，下次启动自动重新打开窗口，并恢复上次保存的窗口位置。
- 代理、错误显示、60 秒自动刷新和本地 CLI 调用规则不变；不复制或接管任何 provider 凭据逻辑。

## 方案与架构

采用 `MenuBarExtra` 加 AppKit `NSWindowController` 的组合，而不是复制一套 App 或依赖第二个进程。

- `DisplayMode`：定义 `.menuBar` 和 `.standaloneWindow` 两个持久化值。
- `DisplayModeSettings`：`@MainActor` 的 `ObservableObject`，读取和写入 `UserDefaults`，对外提供当前模式；模式变更由 App 统一转发给窗口控制器。
- `StandaloneWindowController`：管理唯一的 `NSWindow`，使用 `NSHostingView` 承载与菜单栏详情相同的数据视图，负责创建、显示、关闭、激活和窗口关闭回调。窗口使用固定 autosave name 保存 frame，避免专用小屏的位置在重启后丢失。
- `AiQokkaMenubarApp`：创建一个共享的 `UsageStore`、`DisplayModeSettings` 和窗口控制器；保留现有 `MenuBarExtra`，启动自动刷新，并在持久化模式为独立窗口时异步显示窗口。
- `UsagePopoverView`：增加可复用的显示方式选择器；数据内容仍由同一份 `UsageStore` 驱动，窗口和菜单栏不会各自发起刷新。

独立窗口使用标准标题栏、关闭和最小化能力，内容宽度保持 380pt，高度沿用内容自适应和最大高度滚动策略。这样既能拖动到副屏，也不会因为 provider 数量增加而无限撑高。

## 状态与边界

模式切换只有一个事实来源：`DisplayModeSettings.mode`。选择独立窗口时，控制器创建或复用窗口并激活；选择菜单栏时，控制器关闭窗口。窗口手动关闭只在当前模式仍为独立窗口时回写为菜单栏，避免与程序主动关闭窗口产生循环。

如果读取失败，窗口和菜单栏仍沿用现有错误状态：保留上一次成功快照，并在 provider 卡片或空状态中展示错误，而不是伪造空的使用率数据。窗口模式不改变本地读取权限、代理探测或命令参数。

## 验证

- 单元测试验证默认模式、`UserDefaults` 隔离存取和模式值迁移到新实例后仍一致。
- 运行完整 `swift test`，确保现有 CLI、YAML、代理和 Store 测试继续通过。
- 构建 `dist/aiquokka.app`，手动验证：菜单栏切换到独立窗口、窗口显示完整数据、拖到第二屏、退出重启后位置恢复、从窗口或菜单栏切回菜单栏，以及关闭窗口后的恢复入口。

## 不在本次范围

- 不增加新的 provider、后台守护进程、启动项管理或多窗口实例。
- 不允许用户在 App 内编辑代理、CLI 路径或 provider 凭据。
